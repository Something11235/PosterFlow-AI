# 管理员经营记账与公告

管理员控制台的充值金额、已消耗成本为手动文本记录，存于 `public.admin_bookkeeping`。总账不随日期筛选变化，不自动叠加每日金额。保存只修改记账内容，不修改用户积分、订单或余额。

每日明细单独存于 `public.admin_daily_stats`，以 `stat_date` 为唯一主键，支持同一天反复修改、补记历史日期。包括自动新增用户数、手动充值金额、手动成本、备注、修改人、修改时间和版本。两张表都预留 `extra jsonb` 对象，以便以后增加字段。

日期统一为北京时间（Asia/Shanghai）。每日新增用户统计现存 `profiles` 的注册时间，包含未验证账号；已删除账号不计。首次打开控制台、手动查询或读取日期时更新对应日统计并持久化；不要求站长当天登录，之后查询会按当时仍存在的账号补齐。没有每日定时任务、注册触发器或浏览器定时轮询。它是可重新核对的账号统计快照，不是不可变的注册事件日志。

看板与控制台日期筛选一致，最多一次查询 90 天，展示每日新增用户、充值/成本趋势及逐日明细。用户搜索只作用于用户列表。纯数字金额（最多 12 位整数、两位小数，可为负数）按整数分汇总；空白、含货币符号、单位或说明的文本保留在明细，但不转换为金额。界面展示数字填写天数及文字记录天数，缺失金额不绘制成零；没有以不完整记录推算利润。输入 `0` 表示实际为零。

两张表启用 RLS，撤销 `PUBLIC`、`anon`、`authenticated` 的访问，只有服务端 `service_role` 能访问。新增 RPC 使用 `SECURITY INVOKER`、固定空 `search_path` 并逐对象限定 schema，撤销公开执行权限。控制台原有快照 RPC 仍仅服务端调用，将记账并入同一次快照；不增加打开控制台的网络往返数量。独立 `/api/admin/bookkeeping` 读写接口再次校验管理员身份，写入有类型、长度、日期、请求来源校验。版本比较保护并发修改，返回 409 时保留输入，可选择重新读取后修改。

移除的只是后台“已支付订单”“充值积分”卡片与充值订单监控；支付数据及相关积分结算代码仍保留。旧的 `/api/admin/metrics` 保留支付字段以兼容旧调用，但统计日期口径也统一为北京时间。

公告开始、结束时间的输入和回显都使用北京时间，API 保存为带时区的 UTC 时间。旧版本将 UTC 直接截取到 `datetime-local`，会显示少 8 小时且再次保存可能重复偏移；本次修复后反复编辑保存不再发生偏移。已有公告没有批量改时间，若旧版本曾保存偏移，应由管理员确认期望时间后重新设置。

公告新增“本条公告不再显示”。选择按公告 ID、更新时间及实际内容识别版本，在当前浏览器持久保存；发布新公告或更新已隐藏公告后再次显示。普通关闭仅记录当前会话中看到的公告版本，不再使用会误屏蔽后续新公告的全局关闭标记。网页重新打开、刷新，或恢复可见/焦点时（间隔至少 30 秒）检查新公告，无定时轮询。清理浏览器数据或换设备后偏好不保留，浏览器禁止存储时降级为本次页面内生效。

## 发布与回滚

新增迁移通过 Supabase CLI `migration new admin_bookkeeping` 创建。先应用本次迁移，再发布前后端；不要重复执行已登记迁移。旧版前端能容忍快照不含 `orders`，但回滚后不会展示新增记账区。

网站可回滚到本次发布前的成功部署；保留新增表及手工记账数据。若需要数据库也恢复，使用新迁移恢复旧 `get_admin_metrics` / `get_admin_console_snapshot` 定义，勿删除记账表或改写已执行的迁移。旧网站回滚会恢复其公告时区/关闭行为。
