# 管理员经营记账与公告

管理员控制台的经营总账自动汇总 `public.admin_daily_stats` 截至北京时间今日的全部每日充值与成本，不受日期筛选或用户搜索影响。总账为只读金额，不再手填或单独保存。补记、修改每日记录后，数据库同一次保存返回最新合计；按现存每日行重新求和，同一日期重复保存不会重复累加。原 `public.admin_bookkeeping` 手填总账仍保留，不被覆盖，也不额外加到每日合计中。保存只修改记账内容，不修改用户积分、订单或余额。

每日明细单独存于 `public.admin_daily_stats`，以 `stat_date` 为唯一主键，支持同一天反复修改、补记历史日期。包括自动新增用户数、手动充值金额、手动成本、备注、修改人、修改时间和版本。两张表都预留 `extra jsonb` 对象，以便以后增加字段。

日期统一为北京时间（Asia/Shanghai）。每日新增用户统计现存 `profiles` 的注册时间，包含未验证账号；已删除账号不计。首次打开控制台、手动查询或读取日期时更新对应日统计并持久化；不要求站长当天登录，之后查询会按当时仍存在的账号补齐。没有每日定时任务、注册触发器或浏览器定时轮询。它是可重新核对的账号统计快照，不是不可变的注册事件日志。

看板从 **2026-10-11** 起展示每日新增用户、充值/成本趋势及逐日明细；早于该日的数据不展示，也不计入区间摘要，但已有更早的每日金额仍参与全局总账。控制台默认起始日为该日；若超过现有 API 的 90 天上限，则默认最近 90 天。手动查询可选择之后的子区间；查询更早区间时，看板截去 10 月 11 日之前的记录。用户搜索只作用于用户列表。

纯数字金额（最多 12 位整数、两位小数，可为负数）参与汇总；数据库使用精确 numeric 运算，总账以十进制字符串传输与格式化，避免浮点金额误差。空白、含货币符号、千位分隔符、单位或说明的文本保留在明细，但不转换为金额。总账和区间摘要展示数字填写天数及文字记录天数，无任何数字的金额显示“—”，输入 `0` 才表示实际为零。缺失金额不绘制成零；没有以不完整记录推算利润。

两张表启用 RLS，撤销 `PUBLIC`、`anon`、`authenticated` 的访问，只有服务端 `service_role` 能访问。总账函数 `get_admin_bookkeeping_totals()` 使用 `SECURITY INVOKER`、固定空 `search_path`，仅服务端可执行；读取和保存 RPC 均在内部调用它。控制台原有快照 RPC 仍仅服务端调用，将记账并入同一次快照；不增加打开控制台或保存每日记录的网络往返数量。独立 `/api/admin/bookkeeping` 读写接口再次校验管理员身份，写入有类型、长度、日期、请求来源校验。版本比较保护并发修改，返回 409 时保留输入，可选择重新读取后修改。

移除的只是后台“已支付订单”“充值积分”卡片与充值订单监控；支付数据及相关积分结算代码仍保留。旧的 `/api/admin/metrics` 保留支付字段以兼容旧调用，但统计日期口径也统一为北京时间。

公告开始、结束时间的输入和回显都使用北京时间，API 保存为带时区的 UTC 时间。旧版本将 UTC 直接截取到 `datetime-local`，会显示少 8 小时且再次保存可能重复偏移；本次修复后反复编辑保存不再发生偏移。已有公告没有批量改时间，若旧版本曾保存偏移，应由管理员确认期望时间后重新设置。

公告新增“本条公告不再显示”。选择按公告 ID、更新时间及实际内容识别版本，在当前浏览器持久保存；发布新公告或更新已隐藏公告后再次显示。普通关闭仅记录当前会话中看到的公告版本，不再使用会误屏蔽后续新公告的全局关闭标记。网页重新打开、刷新，或恢复可见/焦点时（间隔至少 30 秒）检查新公告，无定时轮询。清理浏览器数据或换设备后偏好不保留，浏览器禁止存储时降级为本次页面内生效。
