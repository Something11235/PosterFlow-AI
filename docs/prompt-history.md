# 七天提示词历史

侧栏“历史记录”恢复为纯文本窗口：提交时间、提示词原文、复制、填入编辑器。填入不会自动生成或扣积分。历史接口不返回图片键、签名 URL、缩略图、参考图、服务商地址或密钥，窗口不会读取任何图片。

登录用户复用现有 `generation_jobs.prompt`，覆盖平台积分、自带 Key、文生图、局部重绘及画布请求。记录的是服务端已接受并进入现有任务记录流程的请求，含失败任务；未通过参数/身份/余额等前置校验的请求不保证有记录。已有近七天记录直接可见，不新建文本副本或图片历史库。

`GET /api/history` 必须登录，从服务端认证身份限制 `user_id`，忽略查询参数伪造的身份。数据库查询只选 `id,prompt,created_at`，强制 `created_at > now - 7 days`，每页50条；时间与ID组合游标实现稳定翻页。接口设置 private/no-store。只有打开窗口、手动刷新/加载更多时才访问接口；前端一分钟定时器仅在内存中移除过期文本，不发网络请求。切换身份、关闭窗口时取消请求，隔离旧结果。

未登录、自带 Key 的请求只在当前浏览器保存白名单文本字段（包括主编辑器、迭代与画布实际提交的文字）。它们不上传历史服务，也不自动合并进登录账号。超过七天的本机记录在读取、写入时删除，窗口打开时内存也会过期；浏览器关闭期间的本机文本将在下次访问时清除。本机历史最多约100万字符，超出时移除最旧记录；存储满或被禁用时退化为当前页面内存保存。清理浏览器数据或换设备不能恢复本机记录。

新迁移创建私有 `private.prune_prompt_text(boolean)`，以滚动7×24小时为边界，每次最多清空5000条过期 `generation_jobs.prompt`，保留任务行、积分、状态、图片键与运营统计。Cron `posterflow-prompt-text-retention-7d` 每小时第23分钟执行，物理清理通常可延迟一小时；API始终严格过滤七天窗口。清理函数为 SECURITY INVOKER、空 search_path、仅数据库管理员/Cron所有者可执行，应用角色不可调用。不会修改已运行的图片清理任务，也不延长生成结果临时图片的保存时间；参考图和本机画布现有逻辑保留。

发布前可 dry-run 查看过期数量，事务内用临时任务表验证真实清理函数不会改变图片、积分或近期提示词。验证后执行第一次真实文本清理。清理历史文本不可恢复，符合仅保留七天的要求。回滚网站会隐藏入口，但定时文本清理仍继续；若要停止后续清理需显式停用该 Cron，不重写已执行迁移。
