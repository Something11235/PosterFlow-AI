# Nano Banana 2.1 清晰度定价

2026-11-11 版本更新：新增Seedream 5.5及分辨率价格档位；当前规则统一见[图片分辨率与积分](image-resolution-pricing.md)。两份新增迁移已应用。下方旧价格、分辨率入口和Git状态属于历史记录，以新说明及本地交接为准。

2026-10-24 用户指定：1K、2K 每张 1 网站积分，4K 每张 2 网站积分。文生图与参考图编辑同价，参考图数量不额外增加单张价格，最多 8 张参考图、4 张输出保持。自带 API Key 模式不扣网站积分。原三个 GPT、两个 Grok、音乐价格不变。

服务端先校验模型、分辨率和实际参考图，再将规范化请求的 `resolution` 交给仅 service_role 可执行的 `begin_apimart_image_job_v3`。数据库自行决定价格，忽略客户端的任何单价字段。4K 用固定两积分预约路径，原 profile/account 行锁、幂等、余额/邮箱/冻结检查保留；外部上传/生成均在数据库预约事务之后执行。

新任务保存 `pricing_resolution` 与已有 `unit_credit_cost` 快照。4K 的 generation_jobs.metadata.model_cost=2，原结算函数按真实保存张数结算；例如请求 4 张预留 8，保存 1 张最终扣 2、退 6。明确失败全退，重复请求、退款和结算不会重复扣退。查询/保存暂不可确认沿用原保留预约逻辑。管理员积分记录读取实际 charged_credits，无需改写历史数据。

迁移：本地 `20261024092047_nano_4k_pricing.sql`，生产应用版本 `20261024092842/nano_4k_pricing`。只新增可空列、private 定价 helper 和 v3 私有实现/公开 invoker 包装；撤销 public/anon/authenticated 调用，仅 service_role 可执行。所有原 v1/v2、预约和结算函数定义哈希保持不变，不重算任何旧任务/余额/流水。旧 v2 任务用相同请求号走 v3 时仍返回旧价格快照。

前端工作区选择框仍只显示模型名，参数区显示当前清晰度单价和批量合计，服务设置选项/说明和模型一览同步两档价格。自带 Key 参数区说明不扣网站积分。

同轮按用户最终文字调整图像失败建议，两处共享同一句：请修改提示词或更换参考图重试。不同模型的审核力度不同，可更换不同的模型进行尝试。参考图上传失败仍显示上传阶段的独立建议。

回滚只切代码部署，不撤销迁移、不回滚用户/余额/账目。旧版新任务仍遵循旧代码价格；已提交的新 4K 任务保留两积分快照并由原结算函数处理。原 2416911 固定恢复点保留。
