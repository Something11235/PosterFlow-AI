# 图片流量优化

## 画廊缩略图

新生成图片保存原图后，会直接利用服务商已返回的内存数据生成最长边 512 像素、128 色的 PNG 缩略图。原图字节不改动，缩略图失败也不影响本次生成成功或积分结算。

缩略图文件与原图位于同一用户的 `images/` 目录，名称为 `_thumb_<原文件名>.png`。它符合当前 12 小时清理任务的 PNG 筛选规则，无需数据库迁移；手动删除原图时也会删除对应缩略图。清理统计的对象数将包含缩略图，不等于生图张数。

画廊请求 `GET /api/images/<filename>/url?variant=thumbnail`；放大预览、下载、画布导入仍使用原图。接口先鉴权并按用户目录签名，图片本身仍由浏览器直接从 Supabase 读取，不经 Vercel 代理。没有缩略图的旧图片会回退到原图，不批量下载旧图补做缩略图。

缩略图会增加少量存储、上传操作和后端图片处理开销，用来减少日常画廊浏览的出站字节。部署后新生成的图片才具备缩略图；旧图不保证节省。

## 原图复用

当前页面会话中，放大预览、单张下载、画布导入和 ZIP 导出共用原图 Blob 缓存。缓存按登录凭据、文件名和图片类型隔离，并合并同时发起的相同请求；身份变化时清空，并防止旧请求在清空后重新写回缓存。

缓存最多 48 MiB、32 个对象，10 分钟失效，按最近使用情况淘汰；超出单张缓存预算的图片不放入缓存。仅保存在当前页面内存，不写入 localStorage 或新的 IndexedDB。关闭/刷新页面后不保证继续复用。画布已有的本地副本和保存机制不变。

外部 Storage 请求不携带本站 Authorization。读取失败不会缓存错误；过期签名最多重签一次。预览产生的临时 Blob URL 在关闭时释放，下载 URL 延后释放。

## 参考图上传

超过 2 MiB 的普通参考图会尝试在浏览器编码成质量 0.92 的 WebP，最长边不超过 2560 像素，保持宽高比例和透明通道。只有实际节省至少约 10% 才采用结果，否则沿用原图；浏览器不支持或处理失败时也沿用原图。原有 16 MiB 单张安全上限保留。

小参考图和 GIF 不重新编码。局部重绘蒙版通过 `preservePixels: true` 显式跳过压缩，保持字节、尺寸和透明度不变。参考图上传顺序不变，压缩后同步更新请求中的 MIME、大小和文件扩展名。

这会减少上传体积，以及后端随后从 Storage 读取参考图的出站体积；并不把读取变成零流量。参考图压缩可能改变像素，不应将其描述为无损；生成原图及下载文件则不因这项优化而改变。

## 验证与限制

- 单元测试覆盖缩略图格式/尺寸/透明度、原图不变、失败回退、用户隔离、缓存上限/到期/登出、ZIP 原图字节、参考图顺序和蒙版保护。
- 合成噪声 PNG 样本中，缩略图比原图减少约 96%～99% 字节；这不是所有真实图片的节省保证。
- 本地 Chrome 实测：合成参考 PNG 从 15,889,038 字节变为 2,872,662 字节 WebP，尺寸 2560×1536，透明通道保留，蒙版跳过优化。该测试未读取线上用户图片。
- 减少的只是之后实际需要传输的数据，不会抵扣已用流量；下载原图、未命中缓存和首次读取仍会消耗 Storage Egress。

运行检查：`python -m unittest discover -s tests -v`，以及在 `frontend` 下执行 `npm test`、`npm run lint`、`npm run build`。安装后端依赖时会安装固定版本 `Pillow==13.0.0`，支持 Python 3.11 及以上。
